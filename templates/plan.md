# 구현 기획서

이 문서의 질문 대상은 **Probe 내부 메신저의 업무 담당자·실무자 에이전트**입니다. 외부 사람에게 연락하거나 문제·코드·작업물을 전달하지 않습니다.

요구사항 확인 후 가장 먼저 충실히 작성할 문서다. 기능 목록만 나열하지 말고 '무엇을 왜 만들며, 어떤 데이터와 구조로 구현하고, 무엇으로 완료를 확인할지'를 구체화한다. 분량보다 근거·선택·실행 가능성이 중요하다. 과제 작업 공간에 작성하고 시험 지정 양식을 우선한다.

초안 작성 → 실무자 에이전트 확인 → 대안 비교와 사용자 선택 → 첫 구현 범위 확인 → 구현 순서로 진행한다. 미확인 내용은 사실처럼 채우지 않는다. 핵심 결정을 기다리는 동안 독립적인 자료 검사·재현은 계속하고, 사소한 미결 사항 때문에 전체 작업을 멈추지 않는다.

## 우선순위
우선순위는 초안 → 실무자 에이전트 확인 → 사용자 판단 순서로 확정한다. 공식 필수 조건은 별도로 먼저 충족한다.

### 업무 맥락과 질문 계획

- 줄여야 할 손실·시간·오류와 성공 기준:
- README·데이터로 확인한 사실 / 아직 추정인 내용:

| 질문 ID | 실무자 에이전트에게 물을 구체적 질문 | 질문 이유·바뀔 수 있는 결정 | 관련 자료 | 질문 시점 | 상태 |

### 사용자가 결정할 범위와 중요도
| 결정 ID | 선택할 사항 | 실무자 에이전트 답변·데이터 근거 | 선택지와 장단점 | AI 추천·이유 | 사용자 선택·이유 | 상태 |

- 비교 기준 후보: 업무 영향, 오류 피해, 사용 빈도, 데이터 신뢰도, 구현 시간, 검증 가능성.
- 이번 과제에 적용할 기준과 중요도 순서는 사용자에게 묻는다. 숫자 가중치가 필요하다면 사용자에게 값과 이유를 확인한다. 미확정 가중치로 순위를 확정하지 않는다.
- 실무자 에이전트의 의견은 업무 근거이며 공식 평가 배점과 같다고 간주하지 않는다.
- 미답변으로 대기할 작업 / 독립적으로 진행할 작업:

### 첫 구현을 위한 상세 작업

첫 구현은 대표 입력이 검증·핵심 처리를 거쳐 출력까지 이어지는 작은 동작 단위로 정한다. 이 흐름의 정확성을 먼저 확인한 뒤 기능을 넓힌다. 화면이나 부가 기능만 먼저 완성하고 핵심 처리를 나중에 확인하지 않는다.

- 첫 구현의 요구사항 ID·목표:
- 포함할 범위 / 이번 단계에서 제외할 범위:
- 실제 사용할 입력 / 예상 결과와 그 근거:
- 실행 명령·검증 방법 / 실패 시 점검할 지점:

| 작업 ID | 할 일 | 선행 조건 | 완료 확인 방법 | 시간 한도 | 상태(대기/진행/검증 완료) |
|---|---|---|---|---|---|

- 기획·질문·비교에 쓸 시간 / 구현·검증·문서·제출에 남겨둘 시간:
- 지연 시 사용자에게 제시할 범위 조정안:

## 구현 시작 전 확인

- [ ] 필수 조건·제출 경로·환경 제약을 근거와 함께 확인했다.
- [ ] 데이터 의미·품질과 주요 업무 규칙을 확인하거나 미확인으로 구분했다.
- [ ] MVP 범위·우선순위·핵심 기술 선택에 대한 사용자 답변을 기록했다.
- [ ] 구성요소의 역할과 입력 → 처리 → 출력 흐름을 설명할 수 있다.
- [ ] 첫 구현의 입력·기대 결과·완료 검증이 구체적이다.
- [ ] 위험·의존성·남은 시간과 검증·제출 시간을 고려했다.
- [ ] 결정 대기 작업과 독립적으로 진행할 작업을 구분했다.

사용자에게 기획의 핵심과 남은 선택을 보여준 뒤 첫 구현 범위를 확인한다. 이미 같은 범위를 명확히 승인했다면 해당 답변을 기록하고 재확인을 반복하지 않는다. 위 체크는 실제 확인한 것만 표시한다.

## 소통 후 계획 갱신
각 핵심 기능 구현 전후와 중간 결과 검토 때 아래를 확인한다. 애매한 점이 발견되면 즉시 질문하고, 질문이 없다면 억지로 만들지 않는다.

- 새로 추정한 업무 규칙이나 데이터 의미가 있는가?
- 정상·예외 처리 기준 또는 결과의 업무상 의미가 애매한가?
- 누락한 사용자·업무 단계·오류 영향·운영 제약이 있는가?
- 실무자 에이전트 답변으로 해결할 사실과 사용자가 선택할 판단을 구분했는가?

| 확인 시점·기능 | 새 모호점·고려사항 | 즉시 제시할 질문 ID | 답변 대기 작업 | 계속할 작업 | 답변 후 재확인 |
|---|---|---|---|---|---|

| 새 답변·검증 결과 | 기존 가정과 차이 | 사용자에게 다시 물을 결정 | 계획·완료 기준·테스트 변경 |
|---|---|---|---|
