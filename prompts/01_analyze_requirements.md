# 요구사항 분석

이 문서의 질문 대상은 **Probe 내부 메신저의 업무 담당자·실무자 에이전트**입니다. 외부 사람에게 연락하거나 문제·코드·작업물을 전달하지 않습니다.
시험 README와 제공 자료, kit/AGENTS.md를 읽고 아래를 정리해줘.
1. 필수 기능과 선택 기능 (근거 파일·위치 포함)
2. 제출 파일명·경로·형식
3. 허용 기술·설치·네트워크·시간 제약
4. 우선 구현할 MVP와 작업 순서
5. 각 요구사항의 입력·기대 출력·검증 방법
6. 확인되지 않은 사항과 확인 방법
7. 실무자 에이전트에게 확인할 업무 질문: 각 질문에 현재 관찰, 구체적 질문, 답변에 따라 바뀔 결정을 붙여줘. templates/stakeholder_questions.md를 참고해 영향이 큰 3~5개부터 제시해줘.
8. 내가 개발자로 판단해야 하는 항목: MVP 범위, 중요도·가중치, 오류 허용 수준, 시간과 정확성의 절충을 구분해줘. 근거와 선택지·장단점·추천을 제시한 뒤 나에게 선택과 이유를 물어봐. 임의로 확정하지 마.

내가 실무자 에이전트 답변을 전달하면 사실과 해석을 구분하고 후속 질문을 만들어줘.
실무자 에이전트 의견을 공식 배점으로 간주하지 말고, 필수 조건을 충족하면서 내가 우선순위를 판단하도록 도와줘.
미답변 질문과 결정 대기 항목, 그와 무관하게 진행할 수 있는 작업을 구분해줘.

분석 후에는 templates/plan.md를 참고해 과제 작업 공간의 구현 기획서를 우선 충실히 작성해줘. 요구사항별 구현·검증 연결, 데이터 의미·품질, 구성요소별 입출력, 기술 후보, 위험·의존성, 첫 구현의 입력·기대 결과·작업 순서와 시간 예산을 구체화해줘. 비어 있는 핵심 정보를 임의로 채우지 말고 실무자 에이전트 질문과 내가 결정할 선택으로 구분해줘.
기획 요약과 미결 사항을 보여주고 첫 구현 범위를 나에게 확인해줘. 이미 내가 확정한 내용은 다시 묻지 마. 기획 문서는 작성하되 이 분석·기획 단계에서는 구현 코드를 수정하지 마. 요구사항·데이터를 임의로 만들지 마.
kit은 보조 도구이며 실제 과제 폴더와 구분해줘.
