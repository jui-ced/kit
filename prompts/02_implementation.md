# 현재 단계 구현

이 문서의 질문 대상은 **Probe 내부 메신저의 업무 담당자·실무자 에이전트**입니다. 외부 사람에게 연락하거나 문제·코드·작업물을 전달하지 않습니다.
현재 단계: [구현할 요구사항]
관련 파일: [경로]
완료 기준: [입력과 기대 출력]

README와 승인된 계획을 확인하고 현재 단계만 작게 구현해줘.
먼저 구현 기획서의 요구사항·데이터 흐름·구성요소·완료 기준·사용자 선택이 구체적인지 확인해줘. 부족하면 코드부터 작성하지 말고 해당 기획을 보완하고 필요한 선택을 내게 물어봐. 첫 구현은 대표 입력 → 핵심 처리 → 출력이 이어지는 작은 범위로 정하고, 실제 결과를 기획의 기대 결과와 대조한 뒤 확장해줘.
핵심 알고리즘이 아직 확정되지 않았다면 먼저 templates/skill.md를 참고해 문제·목표·제약과 후보 2~3개를 정리해줘. 각 후보의 기본 원리·구성·시간/메모리·해 품질·구현 비용을 비교하고, 추천 이유와 불확실성을 설명한 뒤 나에게 선택과 이유를 물어봐. 내 선택 전에 본 구현에 채택하지 마.
효율 비교는 이론과 실측을 나누고, 실측이 필요하면 비교 실험 범위·시간 예산을 먼저 물어봐. 비교 결과를 보여준 뒤 최종 알고리즘을 선택하게 해줘. 측정하지 않은 배율·개선율을 만들지 마.
변경 전 목적과 선택 이유를 설명하고, 필요한 kit 함수만 검토해 재사용해줘.
원본을 보존하고 기능·의존성을 임의로 추가하지 마.
구현 후 실제 실행 및 관련 테스트를 수행하고 변경 파일·결과·한계를 알려줘.
선택 이유와 검증 결과를 과제 작업 공간의 판단 기록에 남겨줘.
구현 중 문서는 templates/decisions.md의 업무 판단·진행 기록과 templates/skill.md의 기술 설명으로 나눠줘. 업무 결정·질문 ID와 기술 ID를 연결하고 같은 상세 설명을 중복 작성하지 마. 구현 기획서는 별도로 유지하고 새 근거로 계획이 달라지면 함께 갱신해줘.
구현 방향 결정 때와 구현 후에 과제 작업 공간의 templates/skill.md(시험 지정 기록이 있으면 해당 파일)에 추가해줘. 사용한 알고리즘, 기본 구성과 코드 대응, 다른 알고리즘을 선택하지 않은 이유, 사용자 선택·이유, 실제 설정·효율·한계를 기록해줘. 기존 판단을 덮어쓰지 말고 변경 근거와 재결정을 남겨줘.

구현 중 업무 규칙·데이터 의미·예외가 불명확하면 실무자 에이전트에게 물을 구체적인 질문과 이유를 내게 제시해줘.
각 핵심 기능 구현 전후와 중간 결과를 볼 때마다 애매한 부분이나 놓친 고려사항이 있는지 먼저 점검해줘. 발견하면 내가 요청할 때까지 기다리거나 마지막에 몰아서 묻지 말고, 실무자 에이전트에게 바로 전달할 질문 1~3개를 제시해줘.
질문은 '관찰한 사실 → 모호한 점 → 지금 물어야 하는 이유 → 실제 질문 문장 → 답변에 따라 달라질 처리 → 대기/계속할 작업' 순서로 정리해줘. 답변을 받으면 해결됐는지 확인하고 필요한 후속 질문을 이어가줘.
새 정보 때문에 우선순위·가중치·처리 정책·생략 범위를 바꿔야 한다면, 근거와 선택지·장단점·추천을 설명하고 나에게 선택과 이유를 물어봐.
내 답변 전에는 그 결정에 의존하는 변경을 보류하고 독립적인 작업은 계속해줘.
이미 내가 결정한 사항은 새로운 근거 없이 반복해서 묻지 마. 사소한 구현 세부사항은 직접 처리해줘.
실무자 에이전트 답변 → 나의 판단 → 구현 변경 → 실제 검증이 연결되도록 계획과 판단 기록을 갱신해줘.
