README와 승인된 계획을 확인하고 현재 단계만 작게 구현해줘.
변경 전 목적과 선택 이유를 설명하고, 필요한 kit 함수만 검토해 재사용해줘.
원본을 보존하고 기능·의존성을 임의로 추가하지 마.
구현 후 실제 실행 및 관련 테스트를 수행하고 변경 파일·결과·한계를 알려줘.
선택 이유와 검증 결과를 과제 작업 공간의 판단 기록에 남겨줘.

구현 중 업무 규칙·데이터 의미·예외가 불명확하면 현직자에게 물을 구체적인 질문과 이유를 내게 제시해줘.
각 핵심 기능 구현 전후와 중간 결과를 볼 때마다 애매한 부분이나 놓친 고려사항이 있는지 먼저 점검해줘. 발견하면 내가 요청할 때까지 기다리거나 마지막에 몰아서 묻지 말고, 현직자에게 바로 전달할 질문 1~3개를 제시해줘.
질문은 '관찰한 사실 → 모호한 점 → 지금 물어야 하는 이유 → 실제 질문 문장 → 답변에 따라 달라질 처리 → 대기/계속할 작업' 순서로 정리해줘. 답변을 받으면 해결됐는지 확인하고 필요한 후속 질문을 이어가줘.
새 정보 때문에 우선순위·가중치·처리 정책·생략 범위를 바꿔야 한다면, 근거와 선택지·장단점·추천을 설명하고 나에게 선택과 이유를 물어봐.
내 답변 전에는 그 결정에 의존하는 변경을 보류하고 독립적인 작업은 계속해줘.
이미 내가 결정한 사항은 새로운 근거 없이 반복해서 묻지 마. 사소한 구현 세부사항은 직접 처리해줘.
현직자 답변 → 나의 판단 → 구현 변경 → 실제 검증이 연결되도록 계획과 판단 기록을 갱신해줘.
